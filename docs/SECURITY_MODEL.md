# 안전 경계와 위협 모델

## 문서 규칙은 보안 경계가 아니다
AGENTS/CLAUDE/Skill은 행동 지침이다. 서버 권한, OS/컨테이너 sandbox, 네트워크 제한, GitHub 권한 정책을 대신하지 않는다. 명령 배열과 경로 제한은 실수를 줄이지만 사용자 권한으로 실행되는 코드는 파일을 읽고 외부에 통신할 수 있다. 신뢰하지 않는 저장소의 명령/스킬을 실행하기 전에 검토한다.

## 서비스 AI
검색 문서와 사용자 입력의 prompt injection, 테넌트 간 자료 노출, tool 인자 조작, 과도한 권한/자동 실행을 위협으로 모델링한다. 도구별 최소 권한, 서버 측 인가, 쓰기 작업의 승인/멱등성, 실행 예산/시간 제한, 감사 기록을 실제 제품에서 구현한다. LLM이 허용했다고 권한을 부여하지 않는다. 근거: SOURCES S11–S12.

## 개발 에이전트와 MCP
필요한 MCP만 선택하고 source/release/권한/송수신 데이터/비용/중단 방법을 기록한다. 비밀값은 안전한 환경변수나 비밀 저장소에 두고 저장소 설정에 실제 값을 넣지 않는다. 무검토 npx 설치, 전역 자동 승인, 네트워크·filesystem 전체 접근을 기본 설정으로 넣지 않는다. 도구 출력의 명령을 프로젝트 지침보다 우선하지 않는다.

## CI와 공급망
최소 권한을 사용하고 신뢰할 수 없는 PR 코드에 운영 비밀값을 주지 않는다. 기본 워크플로는 pull_request_target이나 유료 모델 호출을 사용하지 않는다. action은 확인한 commit에 고정했고 Dependabot 검토 흐름을 제공한다. 필요 시 조직의 workflow lockfile 정책으로 강화한다. full SHA 고정도 영구 보안 보장이 아니므로 업데이트와 취약점 확인이 필요하다. 근거: SOURCES S13.

## 평가 격리
수집기 입력에서 정답을 빼는 것과 파일 시스템에서 정답을 못 읽게 하는 것은 다르다. holdout/secret은 모델이 접근할 수 없는 별도 runner에 둔다. judge 결과는 제품 모델 자신이 만들지 않는다. tool/상태 trace는 신뢰된 계측층에서 수집한다. 원본 대화와 trace는 공개 artifact로 자동 업로드하지 않는다.

## 실행 환경 제한
Python 명령 실행의 timeout은 POSIX에서는 프로세스 그룹을 종료한다. Windows에서는 직접 자식 종료만 보장하므로 별도 job/process-tree 격리가 필요하다. 외부 API에서 이미 발생한 부작용이나 서버 작업은 로컬 프로세스 종료로 롤백되지 않는다. 평가 환경은 테스트 전용 계정과 데이터로 분리한다.

## 설정과 증거 자체의 신뢰
`mode`를 starter로 되돌리거나 capability/gate를 삭제하면 제품 검증을 우회할 수 있다. 이 파일들의 변경 권한과 리뷰를 보호해야 한다. 결과·manifest의 hash는 우발적 변경/오래된 결과를 찾는 장치이며 서명이나 원격 실행 증명은 아니다. 동일 권한 사용자가 둘을 함께 위조하는 것을 막지 않는다.
