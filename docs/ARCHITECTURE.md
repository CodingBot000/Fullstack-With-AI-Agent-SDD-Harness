# 설계와 경계

## 하나의 개발 체계, 선택 가능한 전문 영역
공통 계약은 `AGENTS.md`, 프로젝트 사실은 `PROJECT_CONTEXT.md`, 개별 변경의 요구사항은 `specs/`에 둔다. UI/백엔드/AI는 개발 관점의 책임 구분이며 배포 분리 지시가 아니다. 단일 서버·모놀리스·별도 AI 서비스 모두 수용한다.

## 지침·스킬·실행 검증의 역할
지침은 해야 할 일을 전달하고 스킬은 반복 절차를 선택적으로 불러온다. 스크립트는 문서 형식·실제 명령 결과·평가 결과를 검사한다. 모델이 지침을 이해하고 따랐는지 완벽히 증명하지는 못한다. 저장소 정책을 우회할 수 있는 사용자를 스크립트만으로 통제하지 않는다.

## 두 하네스
개발 하네스는 저장소 분석, 명세, 구현, 테스트, 리뷰를 지원한다. 서비스 AI 평가 기반은 실제 입력을 대상 서비스에 전달하고 관찰 결과를 채점한다. 서비스의 권한 제어·도구 실행·세션 관리는 해당 제품 코드에서 구현해야 한다. 이 킷은 범용 서버 런타임을 대신하지 않는다.

## 이 킷의 설계 결정
짧은 공통 문서와 작업별 로딩은 OpenAI 하네스 가이드와 Agent Skills의 접근을 참고했다. Spec → Design → Tasks의 산출물 연결은 GitHub Spec Kit의 접근을 참고하지만 Spec Kit CLI를 설치하거나 그대로 복제하지 않았다. `harness/project.json`, CLI 명령, gate 명칭, 생성 스킬 사본은 이 킷의 자체 설계다. 공식 도구의 내장 규격과 구분한다. 근거는 `SOURCES.md`의 S1–S9.

## 의도적으로 넣지 않은 것
특정 LLM 모델명/요금, RAG 프레임워크, vector DB, MCP 서버 자동 설치, 무조건 멀티에이전트, 자동 배포, 자격 증명, 임의 품질 목표. 외부 서비스 연결은 프로젝트에서 선택한다. OS sandbox, DLP, branch protection도 이 Python 코드가 제공하는 기능이 아니다.

## 트레이드오프
정본 스킬을 Claude 경로에 복사하면 저장소 중복은 늘지만 symlink 설정과 OS 차이를 피한다. CI가 사본 불일치를 검출한다. Python 표준 라이브러리만 쓰면 초기 도입은 단순하지만 대규모 평가 병렬화·대시보드·모델 judge·유의성 검정은 제공되지 않는다. 필요 시 검증된 평가 플랫폼을 어댑터로 연결한다.
