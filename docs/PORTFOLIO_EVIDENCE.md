# 경력기술서·포트폴리오에 남길 증거

## 기술 자산과 서비스 성과를 분리
이 저장소를 구축한 사실은 공통 규칙/스킬/검증기/평가기 코드를 통해 보여준다. 실제 서비스를 연결하지 않은 상태에서 풀스택 AI 서비스 운영 경험이나 품질 개선 성과로 표현하지 않는다. 합성 자체 테스트 PASS는 평가 시스템 코드가 예상대로 동작한다는 제한된 증거다.

## 실제 적용 후 남길 것
하나의 변경을 선택해 사용자 문제 → 스펙 → 설계 결정/대안 → 구현 PR → 자동 테스트 → AI baseline/candidate 비교 → 오류 분석 → 최종 승인 순서로 링크한다. 가능하면 첫 적용과 다른 두 번째 프로젝트에 옮긴 과정의 차이도 기록해 범용성을 보여준다.

생산성은 동일 난이도를 가정한 임의 비교 대신 작업 범위·리드타임 정의·리뷰/재작업 포함 여부·표본 수·비교 조건을 기록한다. AI 품질은 dataset/모델/prompt/retrieval/tool policy 버전, 표본/시행 수, slice별 실패, 지연/비용을 함께 기록한다. 코드량이나 스킬 개수만 성과 지표로 내세우지 않는다.

## 검증 가능한 문장 형태
“Codex·Claude Code 공통 SDD/개발 하네스를 구현하고, 스킬 사본 동기화·검증 명령 연결·평가 결과 누락/오염 방지 검사를 자동화했다.”는 실제 구현과 테스트로 확인할 수 있다. “개발시간 N% 단축”, “AI 정확도 N% 향상”, “운영 안정성 확보”는 실제 비교/운영 근거가 있어야 쓴다.

`evidence/case-study.template.md`에 구체적인 사례를 작성한다. 결과 없는 항목은 예정/미검증으로 남기며 숫자를 채우기 위해 만들어내지 않는다.
