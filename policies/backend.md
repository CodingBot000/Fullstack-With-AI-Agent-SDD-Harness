# 백엔드 전문 규칙

이 영역을 변경할 때만 로딩한다. 루트 `AGENTS.md`와 실제 프로젝트 사실이 우선이다.

기존 API·인증·DB·서비스 계층·배포 구조를 확인한다. 언어와 프레임워크를 임의로 교체하지 않는다.

입출력 타입, 오류 응답, 인증/인가, pagination, idempotency, timeout, 재시도 범위를 계약으로 정의한다. 실제 앱 계약과 연결한다.

권한은 서버에서 요청마다 검증하고 사용자/테넌트 데이터 경계를 테스트한다. 요청 ID를 안다고 읽기/쓰기가 허용되지 않는다.

트랜잭션 경계, 중복 실행, 동시성, N+1/쿼리 계획, 연결 풀과 외부 API 실패를 실제 필요에 따라 점검한다.

스키마 변경은 기존 데이터 보존·호환성·백필·배포 순서·복구 가능성을 명세에 남긴다. 운영 DB에 직접 시험하지 않는다.

LLM 호출이 백엔드 안에 있어도 상관없다. 요청 취소 전파, 자원 해제, 과도한 동시 실행과 비싼 재시도를 통제한다.

로그에 토큰/고객 데이터/전체 프롬프트를 무조건 기록하지 않는다. 관측 데이터에도 접근 권한/보존 기간을 적용한다.

완료 증거는 정적 검사·단위/통합 테스트·빌드·권한 부정 테스트다. 프론트엔드와 공유하는 API 계약 검증을 포함한다.
