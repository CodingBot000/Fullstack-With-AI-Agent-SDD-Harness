# 실시간·스트리밍 전문 규칙

이 영역을 변경할 때만 로딩한다. 루트 `AGENTS.md`와 실제 프로젝트 사실이 우선이다.

SSE, fetch streaming, WebSocket, 음성 연결 중 제품 요구에 맞는 방식을 선택한다. 한 방식을 모든 서비스에 강제하지 않는다.

이벤트/메시지 계약, 순서, 종료, 취소, 재연결, 중복, 인증 만료, 부분 실패를 정의한다. HTTP chunk 하나가 완전한 이벤트/문자라는 가정을 하지 않는다.

브라우저 → 백엔드 → 모델/외부 API까지 취소가 전파되는지 확인한다. 연결이 끊겨도 과금·도구 부작용이 계속될 수 있는 상황을 시험한다.

첫 byte/첫 token/첫 의미 있는 응답/완료 지연의 정의를 구분한다. 프록시 buffering, idle timeout, heartbeat, backpressure를 실제 배포 경로에서 확인한다.

부하 테스트는 동시 연결·긴 응답·느린 수신자·반복 재연결을 포함한다. 개발 서버 성공으로 운영 프록시 동작을 추정하지 않는다.

음성 기능은 발화 종료, 끼어들기, echo/중복 입력, 자막/접근성, 개인정보 보존까지 별도 계약과 평가를 만든다. 음성이 없는 제품에는 적용하지 않는다.

참고: SOURCES S15. 이 문서는 연결별 검증 항목이며 프로토콜 구현체가 아니다.
