# 프론트엔드 전문 규칙

이 영역을 변경할 때만 로딩한다. 루트 `AGENTS.md`와 실제 프로젝트 사실이 우선이다.

기존 UI 아키텍처·컴포넌트·상태 관리·라우팅 규칙을 먼저 확인한다. React를 사용하지 않는 프로젝트에 React를 강제하지 않는다.

입력/로딩/부분 응답/빈 결과/실패/취소/재시도 상태를 명세에 연결한다. API 오류와 사용자 상태 복구를 함께 설계한다.

생명주기 정리, 중복 구독, stale 응답, 빠른 화면 이동, 중복 제출을 테스트한다. React를 쓴다면 Effect cleanup과 요청 경합을 실제 코드에서 확인한다.

접근성 이름·키보드 조작·포커스·상태 알림을 검증한다. 테스트는 구현 내부보다 사용자가 관찰하는 결과를 중심으로 작성한다.

대화형 UI는 스트림 중단·최종 응답·오류가 구분되어야 한다. 과도한 스크롤 이동과 전체 메시지 재렌더링을 측정한다.

프런트엔드에 모델 API 비밀키나 권한 판단의 최종 책임을 두지 않는다. 생성된 HTML/Markdown의 출력 처리를 검토한다.

성능 개선은 재현 경로/환경/baseline을 먼저 확보하고 번들·렌더·네트워크 중 병목을 구분한다. 과잉 memoization이나 프레임워크 교체를 기본 해법으로 삼지 않는다.

완료 증거는 실제 정적 검사·단위 테스트·빌드·대표 사용자 경로 E2E다. 브라우저 확인이 없으면 시각/상호작용 검증은 미실행으로 남긴다.

참고: SOURCES S14–S16. 나머지 항목은 본 킷의 프로젝트 적용 체크리스트다.
