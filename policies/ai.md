# AI·LLM 전문 규칙

이 영역을 변경할 때만 로딩한다. 루트 `AGENTS.md`와 실제 프로젝트 사실이 우선이다.

첫 질문은 AI가 필요한 이유와 사용자 과업의 성공 기준이다. 단순 규칙/검색으로 해결할 수 있는 부분을 먼저 구분한다.

직접 모델 호출, 명시적 workflow, 단일 agent, 다중 agent 중 최소 복잡도를 선택한다. 분리는 평가에서 필요가 확인된 경우만 한다.

입력/컨텍스트/출력 계약, 불확실성/거절/근거 부족 처리, 모델/프롬프트 버전, 비용/지연 예산을 정의한다.

문장 유사도나 성공적인 API 호출만으로 고객 의사결정 도움을 평가하지 않는다. 정상/모호/실패/안전 과업과 독립 holdout을 설계한다.

확률적 품질 평가와 결정적 계약/권한 테스트를 구분한다. 모델 judge는 사람 라벨로 교정하고 오판 사례를 관리한다.

모델·프롬프트·검색·도구 정책 변경을 버전화하고 같은 조건의 baseline/candidate를 비교한다. trace는 관측 가능한 실행/결과 중심으로 수집한다.

추론 최적화는 품질·안전성·비용·지연을 함께 본다. 작은 모델/캐시/배칭/컨텍스트 축소가 실제 제품에 적합한지 측정한다. 개인화 캐시의 권한과 만료를 검증한다.

직접 모델을 학습/튜닝하는 경우 데이터 권리·train/eval 누수·가중치/토크나이저/추론 환경 버전·재현성을 추가 명세화한다. API 사용 프로젝트에 학습 인프라를 강제하지 않는다.
