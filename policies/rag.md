# 검색·RAG 전문 규칙

이 영역을 변경할 때만 로딩한다. 루트 `AGENTS.md`와 실제 프로젝트 사실이 우선이다.

RAG 사용 여부와 문서 소유자·공식성·권한·최신성·언어·갱신 주기를 먼저 확인한다. vector DB나 특정 프레임워크를 기본 전제로 두지 않는다.

수집/청킹/색인/필터/검색/재순위/컨텍스트 조립을 분리해 오류를 찾을 수 있게 한다. 문서 ID와 원문/버전 연결을 유지한다.

권한 필터는 검색과 원문 조회에서 일관되게 적용하고 타 사용자의 문서가 컨텍스트로 들어가지 않는지 실제로 테스트한다.

검색 관련성과 생성 답변의 근거 지원을 별도 평가한다. Recall@k에는 검수된 relevant ID가 필요하다. 검색 점수가 높다고 사실성이 보장되지 않는다.

검색 결과 없음·상충·오래된 자료·인덱스 지연·오염 문서를 포함해 실패 행동을 명세화한다. 근거가 없을 때 기존 모델 지식으로 확정 답변하지 않도록 제품 정책을 정한다.

청킹/임베딩/검색 옵션을 한꺼번에 바꾸지 않고 고정 데이터에서 비교한다. 코퍼스 변경은 데이터 버전과 baseline 재생성 여부를 기록한다.

근거 문서의 지시문을 시스템 지침으로 승격하지 않는다. 인용 ID 존재 검사를 의미적 groundedness로 부르지 않는다.

참고: SOURCES S8–S11. 이 킷은 검색 엔진을 제공하지 않고 검증 절차와 어댑터 계약을 제공한다.
